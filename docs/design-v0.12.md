## 一、这次要解决什么

1. 科技里「火力」「后勤」的加成太单一 —— 单发（`click`）和自动（`auto`）的倍率节点数量太多，没有选择。
2. 想要新的手动产出方式 —— 长按开火代替连点，靠科技解锁，后续节点提升每秒自动开火次数。
3. 尸潮目前是"打到 100 发自动触发"，玩家没有控制权，节奏被动。
4. 想要一个开发者调试面板（GM），方便验证和测试。
5. 开火界面太静态，想要"击杀丧尸"的动画反馈。

## 二、机制 A：武器采购折扣

### 2.1 规则

- 新增 `kind: 'weaponDiscount'`，效果是**降低军火库里部分武器的购买价**。
- 只作用于指定档位的武器（"某几个武器"）。
- 计算位置：`weaponCost()`（`game.js:444`），最终价格 = `ceil(baseCost * costMult^n * (1 - 总折扣))`。
- **叠加方式：乘法**（`(1-d1)(1-d2)(1-d3)`），且有**总折扣封顶 40%**（硬限制，写死在 `WEAPON_DISCOUNT_CAP = 0.40`）。乘法保证多个折扣叠起来永远逼近但不超过封顶。

```js
}
```

### 2.2 低档 / 高档怎么分

现有科技是**每分支单链顺序研究**（`techState` 要求前一个节点已 owned），所以把节点排成「低档折扣 → 高档折扣 → 全档折扣」后，玩家自然先解锁便宜枪的折扣，研究到后面才轮到贵枪 —— 正好对应"前置解锁低档武器，后置解锁高档武器"。

档位用 `WEAPONS` 数组下标表达（`game.js:86` 起共 9 档），**已确认（2026-11-11）**：

- `low`：前 4 档 —— 手枪、冲锋枪、霰弹枪、突击步枪
- `high`：后 5 档 —— 狙击步枪、火焰喷射器、榴弹发射器、电磁炮、轨道炮
- `all`：全部 9 档

## 三、机制 B：长按开火（自动连发）

### 3.1 规则

- 前置节点 `kind: 'hold'`：点亮后**长按开火键**持续开火。
- 后续节点 `kind: 'holdCps'`：每级提升"每秒自动开火次数"。

```js
var HOLD_DELAY_MS = 280;   // 按下多久后开始连发
var HOLD_BASE_CPS = 5;     // 长按基础频率（发/秒）  ← 2026-11-11 确认
var HOLD_MAX_CPS  = 10;    // 频率上限              ← 2026-11-11 确认

// cps = clamp(5 + Σ holdCps.value, 0, 10)
// 点满：5 + 2 + 3 = 10 发/秒，正好顶到上限（没有溢出浪费）
```

- 交互：`pointerdown` 延迟 280ms 进入连发；`pointerup` / `pointercancel` / `pointerleave` 立即停。
- 短按（< 280ms）= 单发，保持现在的手感。
- 每一发都走完整的 `fire()`（`game.js:511`），所以暴击、精英、蓝图、尸潮计数全部复用。
- 冷却好了的尸潮按钮可以点了 —— 见机制 C。

### 3.2 技术要点

| 位置 | 要做什么 |
|---|---|
| 配置区 | 新增 `HOLD_DELAY_MS`、`HOLD_BASE_CPS`、`HOLD_MAX_CPS` |
| 科技加成 | 新增 `techHoldCps()`，仿 `techProduct` / `techSum`（`game.js:343`） |
| 输入层 | `ui.fire`（`game.js:1509`，现在是 `click`）改 `pointerdown/up/cancel`；短按仍要触发单发 |
| 计时 | 挂在主 `loop` 里按 `dt` 累加发射时钟，比 `setInterval` 稳，切后台自动停 |
| **渲染节流** | `fire()` 末尾每次都 `render()`，10 发/秒会打爆 DOM。连发时置 `dirty` 标记，由 loop 统一渲染 |
| 浮字 / 震动 | `floatText()` 每发弹字、`navigator.vibrate(8)` 每发抖动 → 连发时合并浮字、关震动 |
| 样式 | `.fire-btn` 加 `touch-action:none; user-select:none; -webkit-touch-callout:none` |
| 存档 | 无需新增字段（`tech` 是通用字典） |

## 四、机制 C：尸潮改为手动按钮触发

### 4.1 规则

- **取消**「开火 100 发自动触发」的累计机制。`HORDE_CLICKS` 及其进度条逻辑废弃（`hordeProgress` 字段保留但恒为 0，兼容旧档）。
- 冷却结束 → 主界面出现/点亮一个**尸潮按钮**，玩家主动点击才触发。
- 不点就一直挂着，尸潮永不发生。
- 触发后进入 `HORDE_SECONDS`（120 秒）增益窗口；结束后进入 `HORDE_COOLDOWN`（300 秒）冷却，如此循环。
- 尸潮的增益保持不变：点击 ×2、精英 ×5、蓝图掉率 ×3。

### 4.2 与旧节奏的对比

| | 旧（v0.11.0） | 新（v0.12.0） |
|---|---|---|
| 触发 | 打满 100 发，自动 | 冷却好了，手动点按钮 |
| 周期 | 约 100 发 ÷ 手速 + 120 + 300 | 固定 120 + 300 = 420 秒 |
| 玩家控制 | 无 | 完全可控（可以攒着不用） |
| 蓝图获取 | 尸潮窗口 ×3 自动获得 | 不点就没有 ×3 窗口，蓝图变慢 |

> ⚠️ 最后一行是实质性的数值变化：蓝图总获取量会下降。需要跑模拟确认，必要时调 `CLICK_BP_CHANCE` 或 `HORDE_BP_MULT` 补偿。

### 4.3 UI

- 复用现有 `#horde-bar`（`game.js:1031` 附近负责渲染），把"进度条"改成"按钮态"：
  - 就绪：按钮高亮 + 文字「尸潮就绪 · 点击释放」
  - 进行中：倒计时 + 点击 ×2 提示
  - 冷却：倒计时
- 点击频率不高，直接 `addEventListener('click', ...)` 即可，不需要防连点（触发后立即进持续态，按钮自动禁用）。

## 五、机制 D：GM 调试面板（连点标题开启）

### 5.1 定位与入口

**已确认（2026-11-11）**：定位是**开发者彩蛋**，不对外宣传、不做 URL 参数、不做密码。

- 入口：顶部标题 `<h1>末日残响</h1>` **连点 7 次**（1.2 秒内）→ 打开 GM 面板，并 toast「GM 模式已开启」。
- 开启后在标题右侧常驻一个 `⚙️` 小按钮，之后一点就开，不用再连点。
- 关闭：面板底部「退出 GM 模式」，清掉 `localStorage.dse_gm` 标记并隐藏按钮。
- `index.html` 需要给 `<h1>` 加一个 id（如 `id="game-title"`）。

> 纯前端游戏没有真正的权限层 —— 玩家开 F12 本来就能改存档，GM 面板只是把这件事变方便。所以它不承担防作弊职责。

### 5.2 第一版范围（用户确认）

只做**四组**：资源、声望、科技、时间。军队 / 军火库 / 尸潮 / 存档暂不进第一版。

| 组 | 操作 | 涉及字段 |
|---|---|---|
| **资源** | 赏金 +1K / +1M / +1B；累计赏金 +1M / +1B / +1T；本局产出清零 | `bounty`、`total`、`runBase` |
| **声望** | 声望 +10 / +100；累计声望 +300（一次性达到科技解锁门槛）；重整次数 +1 | `prestige`、`prestigeTotal`、`prestigeCount` |
| **科技** | 蓝图 +10 / +100；**一键全解**；清空科技；兑换价重置 | `blueprints`、`tech`、`bpBought` |
| **时间** | 游玩时间 +1 小时；模拟离线 8 小时 | `playTime`、`lastSeen` |

几个细节：

- **一键全解**：遍历 `TECH_NODES` 把 `state.tech[id] = 1`，一次点满 21 个节点 —— v0.12 的科技树有 21 个节点，手动点会疯。
- **兑换价重置**：`state.bpBought = 0`，把阶梯价格拉回 25 张/档，配合"蓝图 +100"使用。
- **模拟离线**：`lastSeen` 往前推 8 小时，然后手动调一次 `applyOffline()` 并重绘，不依赖刷新页面。

### 5.3 实现要点

| 位置 | 要做什么 |
|---|---|
| `game.js` IIFE 末尾 | 暴露 `window.__DSE__ = { state, render, save, TECH_NODES }`，**仅在 GM 开启时**挂载 |
| `game.js` 输入层 | 标题 `click` 计数：`1080ms` 内累计 7 次触发；用 `setTimeout` 重置计数 |
| `game.js` 面板 | 复用现有 `.modal` 结构（`#save-modal` 那套），构建 4 组按钮 |
| `style.css` | 复用 `.modal` / `.modal-box` 样式，只补 GM 面板的按钮网格（约 30 行） |
| `tools/smoke-test.mjs` | 所有 GM 的 `ui.*` 必须空值防护（`if (!ui.gmPanel) return;`），否则 DOM stub 下 161 条断言全崩 |
| `README.md` | 加一句「连点标题 7 次可开调试面板」，不展开 |

**通用规则**：每个 GM 操作执行完都要 `render()` + `saveGame()`，否则下一次自动存档会把改动覆盖掉。

### 5.4 注意

1. 改 `total` 会让「生存等级」（`RANKS`）跳级，等级一览里的进度条也会跟着跳 —— 这是预期行为，不是 bug。
2. 改 `blueprints` 时要考虑 `bpBought`，否则兑换价阶梯（`bpPriceAt`）和你给的数量对不上。
3. 改 `prestigeTotal` 到 300 以上才会解锁科技面板（`TECH_UNLOCK_PRESTIGE`）。
4. 与 v0.12 其它改动合并为**同一次** `CACHE` 升级（`dse-v19` → `dse-v20`），不要单独升版本。

## 六、机制 E：击杀动画（开火界面演出）

### 6.1 定位与方案

给开火区加"击杀丧尸"的视觉反馈，**不改现有布局**，只在 `.fire` 按钮上方插一条约 100px 高的舞台。

素材方案已定：**内联 SVG 剪影**（自己写路径，不引入外部图片）。

| 方案 | 要素材 | 观感 | 结论 |
|---|---|---|---|
| Emoji 🧟 + CSS | 不用 | 跨设备字体不一致，安卓可能变彩色方块 | 备选 |
| **内联 SVG 剪影** | **不用** | 跨设备一致，可拆部位单独变形 | **采用** |
| 序列帧 / Lottie | 要（或程序生成） | 最好看 | 留到第二版 |

选 SVG 的理由：直接写在 HTML 里，**没有网络请求**，PWA 缓存不用管；而且能单独控制"头""手臂"这些 `<g>` 分组，做碎尸效果时 emoji 完全做不到。

### 6.2 第一版表现

| 事件 | 表现 | 实现 |
|---|---|---|
| 普通开火 | 丧尸后仰 + 抖动，弹出伤害数字 | SVG + CSS `transform` |
| 暴击 | 数字放大变黄 + 轻震 | 复用 `floatText`，加 class |
| 精英 | 丧尸放大 1.4 倍 + 血条 | 额外 class |
| 击杀 | 碎成 3 块飞散，0.4 秒后重生 | 3 个 `<g>` 分别位移 |
| 尸潮 | 舞台叠红色滤镜 + 影子翻倍 | CSS 类 |

### 6.3 技术要点

| 位置 | 要做什么 |
|---|---|
| `index.html` | `.hero` 里加 `.zombie-stage` + 内联 SVG（约 40 行） |
| `style.css` | 5 个 `@keyframes` + 状态类（约 150 行） |
| `game.js` | `fire()` 末尾调 `playHit()`，与 `floatText()` 并列（约 70 行） |
| 性能 | **只用 `transform` 和 `opacity`**（走 GPU 合成，不改布局） |
| 元素池 | 复用节点对象，不每秒 new 30 个 div 让 GC 抖 |
| 渲染解耦 | 动画层只响应事件，**不进 `render()` 循环** |
| 连发降级 | 超过 8 发/秒时，血花降级成"闪光 + 数字"，不播完整碎尸 |
| 无障碍 | `@media (prefers-reduced-motion: reduce)` 关动画，只留数字飘字 |

### 6.4 工作量

| 部分 | 量级 |
|---|---|
| HTML：舞台 + SVG 剪影 | ~40 行 |
| CSS：keyframes + 状态类 | ~150 行 |
| JS：`playHit()` + 元素池 + 暴击/精英分支 | ~70 行 |
| 冒烟测试补 2~3 条 | ~20 行 |
| **合计** | **~280 行，约半天** |

（加上"碎片飞散 / 血条 / 尸潮演出"更扎实，再加半天。）

### 6.5 依赖关系

**必须排在长按之后。** 长按把开火频率拉到 10 发/秒，动画的元素密度上限、降级策略都依赖长按那一步做出的渲染节流。反过来做（按 6 发/秒设计动画）会在长按上线后返工。

## 七、科技树重构：3×5 + 1×6 = 21 节点

### 7.1 砍节点

| 分支 | 砍掉 | 理由 |
|---|---|---|
| 火力 | `f3` 弹道计算（单发 ×1.20） | 夹在 f2 的 ×1.20 和 f5 的 ×1.25 之间，完全重复 |
| 后勤 | `l2` 弹药工厂（自动 ×1.20） | 与 l1 ×1.15 / l4 ×1.25 同质 |
| 生物 | `b5` 神经加速（单发 ×1.30） | 用户点名第 5 档的单发 |

> 砍中间节点会让后续节点前移，id 需要重排或改用新的顺序索引。建议**重排 id**（`f1..f5` / `l1..l5` / `b1..b5`），旧存档里 `f6`/`l6`/`b5` 这些 id 读到就丢弃（`parseSave` 本来只认 `TECH_NODES` 里存在的 id，见 `game.js:1357`，天然安全）。

### 7.2 新分支：`intel`（智能）

**已确认（2026-11-11）**：第 4 条分支名定为「智能」，id `intel`，图标建议 `🤖`（`💡` 备选）。

6 个节点，折扣 ×3 + 长按 ×3，顺序上折扣与长按交替，避免"半条分支都是折扣"：

| # | id | 名称 | kind | 参数 | 成本 |
|---|---|---|---|---|---|
| 1 | `i1` | 轻武器配额 | `weaponDiscount` | `low`，15% | 40 |
| 2 | `i2` | 速射训练 | `hold` | 解锁长按（5 发/秒） | 72 |
| 3 | `i3` | 重武器配额 | `weaponDiscount` | `high`，15% | 130 |
| 4 | `i4` | 极限采购 | `weaponDiscount` | `all`，15% | 234 |
| 5 | `i5` | 机械扳机 | `holdCps` | +2 发/秒 | 420 |
| 6 | `i6` | 全自动枪机 | `holdCps` | +3 发/秒 | 756 |

- 三条折扣乘法叠加：`1 - 0.85³ = 38.6%`，贴着 40% 封顶但不超，刚好让"封顶"成为防御性参数而不是常态。
  - 如果想让玩家点满后**正好**摸到 6 折，把三档改成 16%：`1 - 0.84³ = 40.7%` → 被 cap 压回 40%，价格恰好 ×0.60。二选一，落地时定。
- 长按最终 cps = `5 + 2 + 3 = 10 发/秒`（不含短按），正好等于 `HOLD_MAX_CPS`。

| 火力 | 15 / 39 / 85 / 186 / 421 | 746 |
