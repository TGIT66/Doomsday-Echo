# 末日残响 / Doomsday Echo（v0.11.0）

一个纯前端的离线放置增量游戏，原创末日丧尸题材。
**个人练习作，仅供自己手机安装使用。**

## 目录结构

本地目录 = 仓库根目录，上传时把这里的**内容**（不是外层文件夹）拖进 GitHub 仓库根目录即可。

```
（仓库根）
├─ index.html      界面结构（顶部状态 + 开火区 + 底部四个 tab）
├─ style.css       样式（冷灰 + 血色 + 警报黄）
├─ game.js         全部游戏逻辑（数值都在文件顶部「配置区」）
├─ manifest.json   PWA 清单，让 Chrome 认它是可安装应用
├─ sw.js           Service Worker，负责离线缓存
├─ CHANGELOG.md    ★ 更新日志：每次改动都记一条，并给版本号
├─ README.md       本文件
├─ icons/          图标（192 / 512，由 tools/make_icons.py 生成）
├─ docs/           设计文档（design-v0.9.md；legacy/ 放旧题材 PRD）
├─ docs/balance/   数值平衡对比图（v0.11.0 调整前后）
└─ tools/          辅助脚本（生成图标、冒烟测试、数值模拟与出图、旧 PRD 生成器）
```

> 游戏必须放在仓库**根目录**，GitHub Pages 的地址才是干净的
> `https://<用户名>.github.io/Doomsday-Echo/`；放进子文件夹会多一层路径。

## 改代码之前先看这个

**每次改动都要做两件事**，缺一个就会出问题：

1. 在 [`CHANGELOG.md`](CHANGELOG.md) 里加一条记录，给个版本号
2. 把 `sw.js` 里 `CACHE = 'dse-vN'` 的 N **+1**

第 2 条最容易被忘。忘了的表现是"代码明明改了，手机上还是老样子"。

## 本地预览

直接双击 `index.html` 就能在电脑浏览器里玩。
（`file://` 下 Service Worker 不生效，但游戏本身照常运行。）

## 当前玩法

- **开火**：点中央的准星按钮，每发造成「单发伤害」点赏金，每 40 发来一只精英（赏金 ×2）；极低概率掉蓝图
- **尸潮**：**开火满 100 发触发**，持续 **120 秒**；期间点击 ×2、精英 ×5、开火掉蓝图概率 ×5。
  结束后进入 **5 分钟冷却**，冷却期间开火**不算有效次数**，冷却走完才从 0 重新累计
- **军火库**：9 把武器，从手枪到轨道炮，成本指数逐档从 ×1.15 抬到 ×1.23（后期更贵），每把同时提供单发伤害和自动赏金；支持「单次 / ×10」批量购买
- **军械里程碑**：每把武器买到 **10 / 25 / 50 / 100 把**各解锁一档，给全局自动、全局单发、以及这把武器自身的产出加成（不再有独立购买的战术装备）
- **营地补给**：离线收益 **2 ~ 8 小时**分档，基础效率 **25%**、上限 60%（首次撤退重整后解锁），且**不吃声望乘区**。回城弹窗里黄色显示**离线时长**与**带回赏金**，超出上限会明确提示
- **生存等级**：10 级，按累计赏金判定（0 → 1e20）
- **军队**：本局产出满 1e6 可撤退重整，声望招募新兵/工兵/军医/军官；**持有声望本身也给全局产能（前 500 点每点 +0.1%，之后递减）**
- **科技**：**累计声望满 300 才开放**；三分支 18 个节点用蓝图研究。蓝图来源：开火掉落（尸潮中 ×3）、声望兑换（25:1 起，每换 10 张涨 15%）

## 部署到手机（Android）

全程不需要命令行、不需要 git。

**路线 A：Cloudflare Drop** —— 打开 <https://cloudflare.com/drop>，把本目录**里面的文件**拖进去，
拿到 `https://xxx.workers.dev`，点 **Claim** 认领成永久网址，手机 Chrome「安装应用」。

**路线 B：Netlify Drop** —— <https://app.netlify.com/drop>，流程同上。

**路线 C：GitHub Pages** —— 把文件上传到仓库**根目录** → Settings → Pages → main / (root) → Save。
地址是 `https://<用户名>.github.io/Doomsday-Echo/`。

> Service Worker 和「安装到主屏幕」都要求 HTTPS，所以必须走一次托管。
> 装好之后就是本地的，跟服务器再没关系。

## 改了代码怎么更新

1. 改完代码，把 `sw.js` 里 `CACHE` 的 N **+1**（当前 `dse-v19`，下次 `dse-v20`）
2. 手机上旧版里**导出存档**（💾 → 导出 → 复制）
3. 重新部署（拖文件夹 / 覆盖上传）
4. 新网址或刷新后，导入存档码

## 想调数值 / 改设定

全部集中在 `game.js` 顶部「配置区」：

- `WEAPONS`：9 把武器，字段 `baseCost` / `costMult` / `rate`（自动赏金）/ `dmg`（单发伤害）。
- `WEAPON_MILESTONES`：军械里程碑，`at`（持有把数）/ `auto` / `click`（加法桶）/ `rate` / `dmg`（只作用于该武器）。
- `RANKS`：生存等级名称与阈值。
- `SOLDIERS`：四种士兵的 `baseCost` / `costMult` / 上限 / `per`（每人的加成量）。
- `TECH_NODES`：18 个科技节点，`kind` 支持 `click` / `auto` / `all` / `off` / `crit` / `eliteReduce` / `eliteMult` / `dropRate`。
- `HORDE_CLICKS` / `HORDE_SECONDS` / `HORDE_COOLDOWN`：尸潮的触发发数（100）、持续秒数（120）、结束后冷却秒数（300，冷却期开火不计数）。
- `HORDE_CLICK_MULT` / `HORDE_ELITE_MULT` / `HORDE_BP_MULT`：尸潮中的点击 / 精英 / 掉蓝图概率倍率。
- `CLICK_BP_CHANCE` / `BP_PRESTIGE_COST` / `BP_PRICE_GROWTH`：开火掉蓝图的基础概率、声望兑换首价、每 10 张的涨幅。
- `PRESTIGE_BONUS_TIERS`：持有声望的被动加成分段（软顶）。
- `OFFLINE_TIERS` / `OFFLINE_MAX_HOURS` / `OFFLINE_BASE_EFF` / `OFFLINE_MAX_EFF`：补给档位、时长与效率上限。
- `PRESTIGE_AT`：撤退重整门槛；`OFFLINE_LOCKED_UNTIL_PRESTIGE`：离线是否要靠转生解锁。
- `ELITE_EVERY` / `ELITE_MULT`：精英丧尸的间隔与**非尸潮时**的赏金倍率（尸潮中另有 `HORDE_ELITE_MULT`）。
- `revealAt()`：列表渐进解锁，规则是「上一档基础成本的一半」，加档位不用改。
- `tools/balance_sim.py` + `tools/balance_charts.py`：改数值前后各跑一次，对比收益曲线（见 `docs/balance-report.html`）。

## 已知边界（本阶段故意不做的）

- 武器改装插槽（设计文档里的 C 方案，v0.6.x 视情况）
- 成就系统、音效
- 云存档（完全离线，只有本地存档 + 存档码）
- 大数库（原生 number 到 1e308 才需要）
